# pi Hiraishi

[English](README.md) | 日本語

[Anthropic Sandbox Runtime](https://github.com/anthropics/sandbox-runtime)（SRT）で、piのファイル操作とHTTP通信を隔離します。
セッションごとにアクセス権限を設定し、通常のツール実行では都度の承認を求めません。

## インストール

Linux（x86-64またはARM64）、Node.js 22.19以上、pi 1.4.x、bubblewrap、socat、ripgrepが必要です。
ユーザー名前空間を利用できる環境で動作します。
SRTは0.0.81に固定しています。

```sh
pi install git:github.com/yoshitsugu/pi-hiraishi
```

Hiraishi本体、依存ライブラリ、Node、設定ファイルは、書き込みを許可するディレクトリの外に配置してください。
このリポジトリを開発する場合も、別途インストールしたコピーを使います。
隔離に失敗した場合、ツールの実行を拒否します。

## 設定

`~/.pi/agent/hiraishi/config.json`に保存します。
piの設定ディレクトリを変更している場合は、その配下の同じ場所を使います。
`HIRAISHI_CONFIG`で別のパスも指定できます。
JSONコメントに対応しており、ファイルがなければ次の既定値を使います。

```json
{
  "networkMode": "off",
  "readOnly": [],
  "readWrite": [],
  "denyRead": []
}
```

セッションの作業ディレクトリは、削除を含めて読み書きできます。
追加のアクセス権限は次の項目で指定します。

- **readOnly**：参照用リポジトリ、ドキュメント、skills、ツールチェーンなど。
- **readWrite**：キャッシュなど、ツールが変更してよいディレクトリ。
- **denyRead**：プロジェクトの`.env`など、読み取りを禁止するファイルやディレクトリ。存在しないパスも指定できます。

パスは絶対パスか`~/...`で指定し、globは使えません。
読み取りや書き込みの許可先には、存在するディレクトリを指定します。
HOME全体やpiの設定ディレクトリ全体は許可できません。
skillsなど、必要なサブディレクトリを指定してください。
実行環境とセッション内部の状態は保護されます。

ツールには専用のHOMEと一時ディレクトリを与え、ホストの環境変数にある認証情報は引き継ぎません。
既知の認証情報のパスは読み取りを禁止しますが、許可先にあるその他の秘密情報は`denyRead`で除外してください。
書き込みはホストの実ファイルに反映されるため、失いたくない作業は別のコピーを残してください。

socatがPATH上になければ、`"socatPath": "/absolute/path/to/socat"`を指定します。
ファイルのアクセス権限を変更したら、新しいセッションか`/reload`で反映します。

## ネットワーク

ユーザーが`/hiraishi-network <mode>`で通信を許可します。
引数を省略すると現在のモードを表示します。

| モード | ツールに許可する通信 |
| --- | --- |
| `off` | 外部通信なし（既定）。 |
| `http-get` | 公開DNSホスト名へのHTTP/HTTPSのGETとHEAD。 |
| `http-all` | 公開DNSホスト名へのすべてのHTTPメソッド。 |

たとえば`/hiraishi-network http-get`で、ドメインごとの確認なしに資料を参照できます。
モデルのプロバイダーとの通信は、`off`でも利用できます。

IPアドレスの直接指定、localhost、プライベートアドレス、ホストのUnixソケット、SSH、任意のTCP/UDP通信、SOCKS、WebSocketへのUpgradeは拒否します。
HTTPSはSRTのTLSプロキシで検査するため、証明書ピンニングやmTLSを使うクライアントは動作しない場合があります。

**GETだけでも、情報の送信やリモートの状態変更は起こり得ます。**
`http-all`ではアップロードやリモートの更新も可能です。
読み取り可能な内容は、モデルのプロバイダーに送信される場合があります。

通信を拒否した後、最新情報やネットワークが役立つ場合は対象作業を一旦止め、オフラインでの続行か通信モードの変更かをユーザーに確認するよう、モデルに指示します。
これはモデルへの指示であり、アクセス権限自体はサンドボックスが強制します。

モード変更時は、実行中のツールと接続を停止します。
中断された呼び出しは再試行が必要で、完了済みの操作は取り消せません。
セッションの切り替えや`/reload`で、設定ファイルの既定モードに戻ります。

## ツール

`read`、`write`、`edit`、`bash`と`!` / `!!`コマンドは同じサンドボックスを使います。
未対応のカスタムツールは拒否します。

`hiraishi_subagent`は親のモデルとアクセス権限を共有します。
既定の`review`モードでは、ファイルの読み取りと固定のGit diff/statusコマンドを使えます。
`work`では、書き込み、編集、bashも使えます。
再帰的な委譲やアクセス権限の変更はできません。

ファイル操作は1ファイル32 MiBまでです。
シェルコマンドの制限時間は既定で120秒、明示指定で最長1時間です。
完了またはキャンセル時に子プロセスも停止するため、常駐するバックグラウンドサーバーには対応しません。

pi本体とインストール済み拡張は、信頼するホストコードとして扱います。
保護範囲と制約の詳細は[SECURITY.md](SECURITY.md)を参照してください。

## 開発

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
```

`HIRAISHI_REQUIRE_SANDBOX=1`で、サンドボックスの前提条件が不足している場合にテストを失敗させます。
`HIRAISHI_TEST_SOCAT=/absolute/path/to/socat`で、テスト専用のsocatを指定できます。
