# pi Hiraishi

[English](README.md) | 日本語

[Anthropic Sandbox Runtime](https://github.com/anthropics/sandbox-runtime)（SRT）で、piのファイル操作とHTTP通信を隔離します。
セッションごとにアクセス権限を設定し、通常のツール実行では都度の承認を求めません。

## インストール

Linux（x86-64またはARM64）、Node.js 22.19以上、pi 1.4.x、bubblewrap、socat、ripgrepが必要です。
ユーザー名前空間を利用できる環境で動作します。
SRTは0.0.81に固定しています。

```sh
pi install git:github.com/yoshitsugu/pi-hiraishi
```

Hiraishi本体、依存ライブラリ、Node、設定ファイルは、書き込みを許可するディレクトリの外に配置してください。
このリポジトリを開発する場合も、別途インストールしたコピーを使います。
隔離に失敗した場合、ツールの実行を拒否します。

## 設定

`~/.pi/agent/hiraishi/config.json`に保存します。
piの設定ディレクトリを変更している場合は、その配下の同じ場所を使います。
`HIRAISHI_CONFIG`で別のパスも指定できます。
JSONコメントに対応しており、ファイルがなければ次の既定値を使います。

```json
{
  "networkMode": "off",
  "maxNetworkMode": "http-all",
  "readOnly": [],
  "readWrite": [],
  "maxReadOnly": [],
  "maxReadWrite": [],
  "denyRead": []
}
```

セッションの作業ディレクトリは、削除を含めて読み書きできます。
追加のアクセス権限は次の項目で指定します。

- **readOnly**：参照用リポジトリ、ドキュメント、skills、ツールチェーンなど。
- **readWrite**：キャッシュなど、ツールが変更してよいディレクトリ。
- **denyRead**：プロジェクトの`.env`など、読み取りを禁止するファイルやディレクトリ。存在しないパスも指定できます。

`networkMode`は起動時のモード、`maxNetworkMode`は`/hiraishi-network`と`--hiraishi-grants`が到達できる上限（`off` ⊆ `http-get` ⊆ `http-all`）です。既定は`http-all`なので、明示的に下げない限り、従来どおり人間がモードを引き上げられます。

`maxReadOnly`と`maxReadWrite`はパスの上限で、grantそのものではありません。セッションには権限を追加しません。`--hiraishi-grants`、`hiraishi_subagent`、host commandの`{cwd}`が使う上限だけを広げるため、呼び出し側は確認ダイアログなしでその配下のパスを要求できます。`maxReadWrite`は書き込みだけでなく読み取りの上限にも含まれます。hostから起動された委譲先の子はどちらの上限も引き継ぎません。子の上限は、親がその子に渡したgrantだけです。

パスは絶対パスか`~/...`で指定し、globは使えません。
読み取りや書き込みの許可先には、存在するディレクトリを指定します。
HOME全体やpiの設定ディレクトリ全体は許可できません。
skillsなど、必要なサブディレクトリを指定してください。
実行環境とセッション内部の状態は保護されます。

ツールには専用のHOMEと一時ディレクトリを与え、ホストの環境変数にある認証情報は引き継ぎません。
既知の認証情報のパスは読み取りを禁止しますが、許可先にあるその他の秘密情報は`denyRead`で除外してください。
書き込みはホストの実ファイルに反映されるため、失いたくない作業は別のコピーを残してください。

socatがPATH上になければ、`"socatPath": "/absolute/path/to/socat"`を指定します。
ファイルのアクセス権限を変更したら、新しいセッションか`/reload`で反映します。

## コマンドラインからの権限付与（他のAIからの利用）

外側のAIは `--hiraishi-grants` でセッション単位の権限を付けて pi をツールとして起動できます。herdr に限らず、シェルスクリプトや別のAIなど、どこからでも同じ形で呼べます。

```sh
pi -e /path/to/pi-hiraishi --hiraishi-grants '{"networkMode":"http-get","readOnly":["/docs"],"readWrite":["/cache"],"denyRead":["/project/.env"]}' --print "最新のドキュメントを読んでAPI連携を更新する"
```

JSONには設定ファイルと同じパス規則で `networkMode`、`readOnly`、`readWrite`、`denyRead` と、任意の `replace` オブジェクトを指定できます（`socatPath` と `hostCommands` は不可）。

- `readOnly`、`readWrite`、`denyRead` は**加算**です。設定ファイルとの和集合になるため、一覧を省略したり短くしたりしても、常時許可の項目が消えることはありません。`denyRead` は増える一方です。
- `replace: { "readOnly": [...], "readWrite": [...] }` を指定したときだけ、そのセッションでベースラインのディレクトリを外せます。`readOnly` と `replace.readOnly` の同時指定はエラーです。置換後もセッション上限の内側でなければなりません。
- `cwd` は想定する作業ディレクトリを固定します。実際の作業ディレクトリが別の場所に解決されるセッションは起動を拒否します。`noHostCommands: true` はそのセッションの `hostCommands` を外し、委譲された子からの再委譲を止めるために使います。どちらも権限を強める方向にしか働きません。
- `networkMode` は起動時のモード、`maxNetworkMode` はその実行のセッション上限です。`{"networkMode":"off","maxNetworkMode":"http-get"}` なら、ネットワークoffで開始しつつ `http-get` まで許可できます。矛盾する指定は、同じ要求内で `networkMode` が `maxNetworkMode` を超えていれば拒否し、`maxNetworkMode` だけが設定既定より低ければ開始モードをそこまで下げます。どちらも設定の `maxNetworkMode` を超える場合はユーザーの承認が必要で、承認された値がそのセッションの上限になります。
- 設定の `maxReadOnly` と `maxReadWrite` はパスの上限だけを広げます。その配下のパスを要求しても上限の内側なので、起動時のダイアログは出ません。これらの項目自体は設定専用で、`--hiraishi-grants` では拒否します。

上限を超える要求は、対話セッションではユーザーに確認します（要求どおり許可 / ベースラインで開始 / 拒否）。「ベースラインで開始」は要求の追加分だけを捨て、制限する指定は残します。`denyRead` の追加、`noHostCommands`、`replace` による絞り込み、上限の引き下げはそのまま適用されます。対話UIがない場合は、拒否または不正な要求の時点でプロセスを終了し、理由をstderrに出します。それ以外の起動失敗は従来どおり、ツールが使えない状態でセッションが残ります。

grantのパスは読み込み時とマージ時に正規化し、ポリシーを組み直すたびに「許可パスが今もそれ自身に解決されるか」を再検証します。許可済みパスの上にシンボリックリンクを被せると、次回のサンドボックス起動が失敗します。決定した権限は、`/hiraishi-network`、サブエージェント、host commandのgrantすべての上限になります。

## host command

サンドボックスから届かないhost側のプログラムが必要な場合があります。Unixソケットで通信するターミナル多重化ツールの制御クライアントが典型です。`hostCommands` でそれらを明示的に宣言します。設定がなければ何も実行されません。

```json
{
  "hostCommands": [
    {
      "name": "hc",
      "path": "/usr/bin/hc",
      "starts": "run",
      "operations": [
        { "name": "run", "argv": ["run", "--bg", "--name", "{name}", "--cwd", "{cwd}", "pi", "-e", "{hiraishi}", "--hiraishi-grants", "{grants}", "{task}"] },
        { "name": "send", "argv": ["send", "{name}", "{task}"] },
        { "name": "read", "argv": ["read", "--lines", "{lines}", "{name}"] },
        { "name": "list", "argv": ["ls"] }
      ]
    }
  ]
}
```

`hiraishi_host` がこれらの操作をモデルに公開します。モデルはバイナリを選べず、フラグを追加できず、シェルも使えません。プレースホルダに型付きの値を受け渡すだけで、各プレースホルダは引数1個を丸ごと占める必要があります。`{hiraishi}` は実行中の拡張のパスです。`{cwd}` は既存のディレクトリに限ります。セッションの作業ディレクトリと書き込みgrantはそのまま許可し、設定の `maxReadWrite` の内側にあるディレクトリも確認なしで許可します。それ以外のディレクトリは、対話セッションではユーザーに確認します。表示する内容は、コマンド名、operation、解決後の `cwd`、子に実際に渡す `{grants}` のJSON、`{task}` の冒頭です。制御文字は無害化します。対話UIがない場合は拒否します。子の作業ディレクトリは書き込み可能になるため、書き込み上限にも入っていない読み取り専用パスは指定できません。`{task}` は `-` や `@` で始められません。開始先のプログラムがオプションやファイル引数として解釈するためです。

コマンドの項目には `env` も指定できます。hostの `pi` プロセスからそのコマンドへ渡す環境変数名のallowlistで、固定の環境変数(`HOME`、`PATH`、`TERM`、ロケール、XDG、D-Bus)に加算します。名前は `[A-Za-z_][A-Za-z0-9_]*` に限り、設定の読み込み時に検証します。変数の値はhostのプロセスにある場合だけ渡します。`env` は設定ファイル専用で、`hostCommands` 自体と同じく `--hiraishi-grants` では指定できません。Hiraishiはツール固有の環境変数を追加しないため、ターミナル制御クライアントの呼び出し元識別など、継承した変数が必要なプログラムはここに名前を書く必要があります。たとえばコマンドの項目に `"env": ["CONTROL_SOCKET", "SERVICE_TOKEN"]` を加えます。渡した値は宣言したコマンドの通常のプロセス環境になり、トークンやソケットのパスはそのコマンドに相応の権限を与えます。信頼できるプログラムだけを宣言し、そのプログラムに必要な名前だけを渡してください。

`{grants}` は `starts` に指定した操作と、`{hiraishi}` を含む操作で必須です。子が自分の設定に戻って上限を迂回できないようにするためです。`{hiraishi}` を付けずにhostの `pi` を起動する操作は、Hiraishiの外で動くので、その場合は両方のプレースホルダを書いてください。bridgeは子のgrantを常に組み直します。要求されたパスを設定のベースラインと交差させ、このセッションがまだ許可しているベースラインの項目を `replace` で明示し、`networkMode` と `maxNetworkMode` をセッション上限で頭打ちにし、セッションの `denyRead` を和集合で加え、想定する作業ディレクトリを `cwd` として固定して子自身に検証させ、`noHostCommands` で再委譲を止めます。委譲先の子には `maxReadOnly` と `maxReadWrite` を渡しません。子のパスの上限は、このセッションが渡したgrantだけです。設定が保持できないパスの要求は、黙って捨てずに拒否します。`{name}` を取る操作は、同じセッションで同じコマンドが起動した子だけを対象にします。セッションの切り替えやキャンセルでその一覧は消え、実行中のhost呼び出しも中断されます。中断で止まるのは直接のhostプロセスだけで、hostプログラムがバックグラウンドで起動した子は残ります。その子はリセット後、このセッションから操作できません。

## ネットワーク

ユーザーが`/hiraishi-network <mode>`で通信を許可します。
引数を省略すると現在のモードを表示します。

| モード | ツールに許可する通信 |
| --- | --- |
| `off` | 外部通信なし（既定）。 |
| `http-get` | 公開DNSホスト名へのHTTP/HTTPSのGETとHEAD。 |
| `http-all` | 公開DNSホスト名へのすべてのHTTPメソッド。 |

たとえば`/hiraishi-network http-get`で、ドメインごとの確認なしに資料を参照できます。
モデルのプロバイダーとの通信は、`off`でも利用できます。

IPアドレスの直接指定、localhost、プライベートアドレス、ホストのUnixソケット、SSH、任意のTCP/UDP通信、SOCKS、WebSocketへのUpgradeは拒否します。
HTTPSはSRTのTLSプロキシで検査するため、証明書ピンニングやmTLSを使うクライアントは動作しない場合があります。

**GETだけでも、情報の送信やリモートの状態変更は起こり得ます。**
`http-all`ではアップロードやリモートの更新も可能です。
読み取り可能な内容は、モデルのプロバイダーに送信される場合があります。

通信を拒否した後、最新情報やネットワークが役立つ場合は対象作業を一旦止め、オフラインでの続行か通信モードの変更かをユーザーに確認するよう、モデルに指示します。
これはモデルへの指示であり、アクセス権限自体はサンドボックスが強制します。

モード変更時は、実行中のツールと接続を停止します。
中断された呼び出しは再試行が必要で、完了済みの操作は取り消せません。
セッションの切り替えや`/reload`で、設定ファイルの既定モードに戻ります。

## ツール

`read`、`write`、`edit`、`bash`と`!` / `!!`コマンドは同じサンドボックスを使います。
未対応のカスタムツールは拒否します。
`hiraishi_host`は`hostCommands`で宣言した操作だけを実行します。

`hiraishi_subagent`は、呼び出しごとに独立したサンドボックスを作成します。
親のネットワークモードや設定ファイルの追加権限にかかわらず、既定ではネットワークoff、作業ディレクトリのみアクセス可能な状態で開始します。
システム実行環境と専用のHOME、一時ディレクトリは利用でき、設定済みの`denyRead`は引き継ぎます。
既定の`review`モードでは、ファイルの読み取りと固定のGit diff/statusコマンドを使えます。
`work`では、書き込み、編集、bashも使えます。
再帰的な委譲や子自身による権限変更はできません。

親は、必要な追加権限を`permissions.networkMode`、`permissions.readOnly`、`permissions.readWrite`で明示し、`reason`に理由を指定できます。
親には、ユーザーの承認済みの作業範囲に含まれる権限だけを許可するよう指示します。
ネットワークはセッション上限まで要求できますが、ディレクトリはセッションのパス上限（設定のgrantと `maxReadOnly`、`maxReadWrite`）の内側に限られます。セッション自身が要求できないパスを子に渡すことはできません。
セッションの上限を超える権限は、`permissions.approval`が`"user"`でない限り拒否します。`"user"`の場合は、上限超過の内容を示したうえで、キャンセル、既定権限で実行、要求された権限で実行の選択肢をユーザーに表示します。
対話UIがない環境では、ユーザーの選択が必要な呼び出しを停止します。
親の判断はモデルへの指示であり、選択後のアクセス制限はSRTが強制します。
追加権限はその呼び出しだけに適用し、親や次の子には引き継ぎません。
子が制限に阻まれた場合は、操作と理由を親へ返し、親が追加許可と再実行を判断します。

モデルは`model: { "provider": "...", "id": "..." }`で指定できます。
piに登録されたチャットモデルを、providerをまたいで選択でき、hiraishi独自のモデル制限は設けません。
未指定なら親と同じモデルを使います。
providerの認証はpiがホスト側で処理し、サンドボックスへ認証情報を渡しません。
モデルが未登録の場合やproviderでエラーが発生した場合は、別モデルへ切り替えずに停止します。

ツール引数の例です（providerとIDは登録済みのモデルに置き換えてください）。

```json
{
  "task": "最新のAPIドキュメントを参照してAPI連携を更新する",
  "mode": "work",
  "model": { "provider": "your-provider", "id": "your-model-id" },
  "permissions": {
    "networkMode": "http-get",
    "approval": "user",
    "reason": "最新のAPIドキュメントを読むためにネットワークが必要"
  }
}
```

ファイル操作は1ファイル32 MiBまでです。
シェルコマンドの制限時間は既定で120秒、明示指定で最長1時間です。
完了またはキャンセル時に子プロセスも停止するため、常駐するバックグラウンドサーバーには対応しません。

pi本体とインストール済み拡張は、信頼するホストコードとして扱います。
保護範囲と制約の詳細は[SECURITY.md](SECURITY.md)を参照してください。

## 開発

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
```

`HIRAISHI_REQUIRE_SANDBOX=1`で、サンドボックスの前提条件が不足している場合にテストを失敗させます。
`HIRAISHI_TEST_SOCAT=/absolute/path/to/socat`で、テスト専用のsocatを指定できます。
