# pi Hiraishi

[English](README.md) | 日本語

[Anthropic Sandbox Runtime](https://github.com/anthropics/sandbox-runtime)（SRT）で、piのファイル操作とHTTP通信を隔離します。
セッションごとにアクセス権限を設定し、通常のツール実行では都度の承認を求めません。

## インストール

必要なもの：Linux（x86-64またはARM64）、Node.js 22.19以上、pi 1.4.x、bubblewrap、socat、ripgrep。ユーザー名前空間を使える環境で動作します。SRTは0.0.81に固定しています。

```sh
pi install git:github.com/yoshitsugu/pi-hiraishi
```

- Hiraishi本体、依存ライブラリ、Node、設定ファイルは、書き込みを許可するディレクトリの外に置いてください。
- このリポジトリを開発する場合も、別途インストールしたコピーを使います。
- 隔離に失敗した場合、ツールの実行は拒否されます。

## 設定

`~/.pi/agent/hiraishi/config.json`に保存します（piの設定ディレクトリを変えている場合はその配下）。
`HIRAISHI_CONFIG`でパスを変更でき、JSONコメントも書けます。ファイルがなければ次の既定値を使います。

```json
{
  "networkMode": "off",
  "maxNetworkMode": "http-all",
  "readOnly": [],
  "readWrite": [],
  "maxReadOnly": [],
  "maxReadWrite": [],
  "denyRead": []
}
```

セッションの作業ディレクトリは、削除を含めて読み書きできます。それ以外は次の項目で許可します。

| 項目 | 用途 |
| --- | --- |
| `readOnly` | 参照用リポジトリ、ドキュメント、skills、ツールチェーンなど（読み取りのみ）。 |
| `readWrite` | キャッシュなど、ツールが変更してよいディレクトリ。 |
| `denyRead` | `.env`など、読ませないファイルやディレクトリ。存在しないパスも指定できます。 |
| `networkMode` | 起動時のネットワークモード（後述）。 |
| `maxNetworkMode` | 実行中に引き上げられるモードの上限。既定は`http-all`で、人間がいつでも引き上げられます。 |
| `maxReadOnly`<br>`maxReadWrite` | 確認なしで許可できるパスの上限（次の段落）。 |

`maxReadOnly`と`maxReadWrite`は、それ自体では何も許可しません。`--hiraishi-grants`、`hiraishi_subagent`、host commandの`{cwd}`が要求したパスのうち、この配下にあるものだけが、確認ダイアログなしで通ります。`maxReadWrite`は読み取りの上限にも含まれます。

パスの書き方：
- 絶対パスか`~/...`で書きます。globは使えません。
- 許可先には、存在するディレクトリを指定します。
- HOME全体や、piの設定ディレクトリ全体は許可できません。必要なサブディレクトリだけを指定してください。

安全のために：
- ツールには専用のHOMEと一時ディレクトリを渡し、ホストの環境変数にある認証情報は引き継ぎません。
- 既知の認証情報のパスは自動で読み取り禁止です。許可先にあるそのほかの秘密情報は、`denyRead`で除外してください。
- 書き込みはホストの実ファイルに反映されます。失いたくない作業は、別のコピーを残してください。

socatがPATHにない場合は、`"socatPath": "/absolute/path/to/socat"`を指定します。
設定を変更したら、新しいセッションか`/reload`で反映されます。

## ネットワーク

人間が`/hiraishi-network <mode>`で切り替えます。引数なしで現在のモードを表示します。

| モード | 許可する通信 |
| --- | --- |
| `off` | 外部通信なし（既定）。 |
| `http-get` | 公開DNSホスト名へのHTTP/HTTPSのGETとHEAD。 |
| `http-all` | 公開DNSホスト名へのすべてのHTTPメソッド。 |

- モデルのプロバイダーとの通信は、`off`でも使えます。
- 次は拒否します：IPアドレスの直接指定、localhost、プライベートアドレス、ホストのUnixソケット、SSH、任意のTCP/UDP、SOCKS、WebSocketのUpgrade。
- HTTPSはSRTのTLSプロキシで検査します。証明書ピンニングやmTLSを使うクライアントは動かないことがあります。
- **GETでも、情報の送信やリモートの状態変更は起こり得ます。** `http-all`ではアップロードやリモートの更新もできます。読み取れる内容は、モデルのプロバイダーに送信される場合があります。
- 通信が拒否されたとき、モデルは作業を止め、オフラインで続けるかモードを変えるかをユーザーに確認します。これはモデルへの指示で、権限そのものはサンドボックスが強制します。
- モード変更時は、実行中のツールと接続を止めます。中断された呼び出しは再試行が必要で、完了済みの操作は取り消せません。
- セッションの切り替えや`/reload`で、設定ファイルのモードに戻ります。

## ツール

`read`、`write`、`edit`、`bash`と`!` / `!!`コマンドは、同じサンドボックスで動きます。
未対応のカスタムツールは拒否します。

- ファイル操作は1ファイル32 MiBまでです。
- シェルコマンドの制限時間は既定120秒で、指定すれば最長1時間です。
- 完了やキャンセルで子プロセスも止まるため、常駐するバックグラウンドサーバーは使えません。

### hiraishi_subagent

呼び出しごとに、独立したサンドボックスで子を動かします。

- 既定では、ネットワークoff、作業ディレクトリのみアクセス可能です。親のモードや設定の追加権限は引き継ぎません。設定の`denyRead`は引き継ぎます。
- `review`モード（既定）：ファイルの読み取りと、固定のGit diff/statusだけ使えます。
- `work`モード：書き込み、編集、bashも使えます。
- 子は再帰的に委譲できず、自分の権限も変更できません。
- `model: { "provider": "...", "id": "..." }`でモデルを指定できます。未指定なら親と同じモデルです。モデルが未登録の場合やproviderのエラーでは、別モデルに切り替えずに止まります。認証はpiがホスト側で処理し、サンドボックスには渡しません。

**権限を足す（`permissions`）**
- `networkMode`、`readOnly`、`readWrite`と、理由を書く`reason`を指定できます。権限はその呼び出しだけに効きます。
- ネットワークは、セッションの上限まで要求できます。ディレクトリは、セッションのパス上限（設定の許可と`maxReadOnly`、`maxReadWrite`）の内側に限ります。
- 上限を超える要求は拒否されます。`"approval": "user"`を付けると、ユーザーに「キャンセル / 既定権限で実行 / 要求どおり実行」を確認します。対話UIがない環境では止まります。
- 親には、ユーザーが承認した作業の範囲だけを要求するよう指示します。これはモデルへの指示で、選択後の制限はSRTが強制します。

**権限を絞る（`permissions`）**
- `denyRead`：子だけが読めないパス。セッションと設定の`denyRead`に追加され、既存の項目は外せません。
- `workspace`：親の作業ディレクトリ配下の既存ディレクトリ。子の作業ディレクトリ兼読み書きの既定範囲になります。親の外、存在しないパス、外へ解決されるsymlinkは拒否します。
- どちらも絞るだけなので、承認は不要です。
- 子が必要とするファイルを隠すと、読み取りが失敗します。子は他のパスを探らず、制約として報告します。
- `workspace`がリポジトリの一部だけを指す場合、`.git`を読めないため、`review`の`git_diff`と`git_status`は使えません。

**限界**
- 制御はパスに基づきます。ハードリンクやbind mountなどの別名で同じデータに届く場合は分離できません。完全なデータの境界ではありません。
- `workspace`の外への書き込みは、エラーにならずに捨てられることがあります。成果物は`workspace`の内側に書かせ、必要なら親から存在を確認してください。

ツール引数の例（providerとIDは、登録済みのモデルに置き換えてください）：

```json
{
  "task": "最新のAPIドキュメントを参照してAPI連携を更新する",
  "mode": "work",
  "model": { "provider": "your-provider", "id": "your-model-id" },
  "permissions": {
    "networkMode": "http-get",
    "approval": "user",
    "reason": "最新のAPIドキュメントを読むためにネットワークが必要"
  }
}
```

## host command

サンドボックスから届かないhost側のプログラムを使いたいときに、`hostCommands`で宣言します。典型例は、Unixソケットで通信する端末多重化ツールの制御クライアントです。設定がなければ何も実行されません。

```json
{
  "hostCommands": [
    {
      "name": "hc",
      "path": "/usr/bin/hc",
      "starts": "run",
      "operations": [
        { "name": "run", "argv": ["run", "--bg", "--name", "{name}", "--cwd", "{cwd}", "pi", "-e", "{hiraishi}", "--hiraishi-grants", "{grants}", "{task}"] },
        { "name": "send", "argv": ["send", "{name}", "{task}"] },
        { "name": "read", "argv": ["read", "--lines", "{lines}", "{name}"] },
        { "name": "list", "argv": ["ls"] }
      ]
    }
  ]
}
```

モデルは`hiraishi_host`で、宣言された操作を呼べます。バイナリの選択、フラグの追加、シェルの利用はできません。モデルが渡せるのは、プレースホルダの値だけです。

### プレースホルダ

各プレースホルダは、引数1個を丸ごと占めます。

| 名前 | 内容 |
| --- | --- |
| `{name}` | 起動した子の名前。 |
| `{cwd}` | 既存のディレクトリ。子の作業ディレクトリと、読み書きの既定範囲になります。 |
| `{task}` | 依頼文。`-`と`@`で始められません（起動先がオプションやファイルとして解釈するため）。 |
| `{grants}` | 子に渡す権限のJSON。 |
| `{lines}` | 読み取る行数（0〜2000の整数）。 |
| `{timeout}` | この呼び出しの制限時間（秒）。 |
| `{hiraishi}` | 実行中のHiraishiのパス。 |

`{cwd}`の扱い：
- セッションの作業ディレクトリ、書き込みgrant、`maxReadWrite`の内側は、確認なしで使えます。
- それ以外は、対話セッションでユーザーに確認します（コマンド名、操作、解決後の`cwd`、子に渡す`{grants}`、`{task}`の冒頭を表示）。対話UIがなければ拒否します。
- 子の作業ディレクトリは書き込み可能になるため、書き込み上限の外にある読み取り専用パスは指定できません。
- サブディレクトリを指定すると、子の範囲をそこに絞れます。`{grants}`の`denyRead`で、その中の一部を隠すこともできます。
- `{cwd}`の外への書き込みは、エラーにならずに捨てられることがあります。成果物は`{cwd}`の内側に書かせてください。

### 子を起動する操作

子を起動する操作（`starts`で指定する）と、`{hiraishi}`を含む操作には、`{grants}`が必須です。子が自分の設定に戻って上限を迂回するのを防ぐためです。
`{hiraishi}`を付けずにhostの`pi`を起動する操作は、Hiraishiの外で動きます。その場合は、両方を書いてください。

子の権限は、bridgeが毎回、次のように組み直します。
- 要求されたパスと、設定の許可の共通部分だけを渡します。
- ネットワークのモードと上限は、セッションの上限までに制限します。
- セッションの`denyRead`を加えます。
- 想定する作業ディレクトリを固定します（子自身が検証します）。
- `maxReadOnly`と`maxReadWrite`は渡しません。
- `starts`を持つコマンドは渡しません（子が再委譲できません）。
- 設定が保持できないパスの要求は、捨てずに拒否します。

`{name}`を取る操作は、同じセッションで同じコマンドが起動した子だけを対象にします。セッションの切り替えやキャンセルで、その一覧は消え、実行中のhost呼び出しも中断されます。ただし、止まるのは直接のhostプロセスだけです。そのプログラムがバックグラウンドで起動した子は残り、このセッションからは操作できません。

### 環境変数（`env`）

hostの`pi`プロセスから、そのコマンドへ渡す環境変数名のallowlistです。

- 固定の環境変数（`HOME`、`PATH`、`TERM`、ロケール、XDG、D-Bus）に追加されます。
- 名前は`[A-Za-z_][A-Za-z0-9_]*`に限り、読み込み時に検証します。
- 値は、hostのプロセスに存在する場合だけ渡します。
- 設定ファイル専用で、`--hiraishi-grants`では指定できません。
- Hiraishiはツール固有の変数を追加しません。呼び出し元の識別などで継承した変数が必要なプログラムは、ここに名前を書きます。

```json
"env": ["CONTROL_SOCKET", "SERVICE_TOKEN"]
```

渡した値は、そのコマンドの通常のプロセス環境になります。トークンやソケットのパスは、コマンドに相応の権限を与えます。信頼できるプログラムだけを宣言し、必要な名前だけを渡してください。

### 子に残すコマンド（`delegable`）

`"delegable": true`を付けたコマンドは、委譲された子にも残ります。既定は`false`です。

- `starts`との併用は、読み込み時に拒否します。
- operationで`{hiraishi}`と`{grants}`は使えません。
- 親がまだ持っているコマンドだけが渡されます。`{grants}`で名前を足すことはできません。
- 残したコマンドは、子の権限でhost上のプログラムを動かします。サンドボックス内でテストを回す専用ラッパーなど、委譲してよいと確信できる固定コマンドだけに付けてください。

## コマンドラインからの権限付与

外側のAIや、シェルスクリプトから、`--hiraishi-grants`でセッション単位の権限を付けて、piを起動できます。

```sh
pi -e /path/to/pi-hiraishi --hiraishi-grants '{"networkMode":"http-get","readOnly":["/docs"],"readWrite":["/cache"],"denyRead":["/project/.env"]}' --print "最新のドキュメントを読んでAPI連携を更新する"
```

JSONで指定できる項目：

| 項目 | 内容 |
| --- | --- |
| `networkMode` | 起動時のモード。 |
| `maxNetworkMode` | この実行の上限。 |
| `readOnly`<br>`readWrite`<br>`denyRead` | 設定ファイルの内容に**追加**されます。設定済みの許可は、ここに書かなくても残ります。`denyRead`は追加だけで、減らせません。 |
| `replace` | `{"readOnly": [...], "readWrite": [...]}`。指定したときだけ、設定の許可を外して置き換えます。`readOnly`と`replace.readOnly`の同時指定はエラーです。置き換えた結果も、セッションの上限の内側に収まる必要があります。 |
| `cwd` | 想定する作業ディレクトリ。実際の作業ディレクトリが別の場所に解決されるセッションは、起動を拒否します。 |
| `hostCommands` | 残す設定済みコマンドの名前の一覧。それ以外は外れます。存在しない名前と、`starts`を持つコマンドは拒否します。 |
| `noHostCommands` | `true`で、すべてのhost commandを外します。`hostCommands`と併用すると、その名前だけが残ります。 |

- どの項目も、権限を絞る方向か、設定の上限の内側でしか働きません。`socatPath`、`maxReadOnly`、`maxReadWrite`は指定できません。
- `networkMode`と`maxNetworkMode`は、`{"networkMode":"off","maxNetworkMode":"http-get"}`なら、offで始めて`http-get`まで上げられます。`networkMode`が`maxNetworkMode`を超える指定は拒否します。設定の`maxNetworkMode`を超える値は、ユーザーの承認が必要で、承認された値が上限になります。
- 空の`hostCommands: []`は、`noHostCommands: true`と同じで、すべて外します。

**上限を超える要求**
- 対話セッションでは、ユーザーに「要求どおり許可 / ベースラインで開始 / 拒否」を確認します。
- 「ベースラインで開始」は、権限を足す分だけを捨てます。`denyRead`の追加、`noHostCommands`、`hostCommands`と`replace`による絞り込み、上限の引き下げは、そのまま適用されます。`replace`はフィールド単位で判定し、すべてのパスが上限の内側にあるフィールドは絞り込みとして適用し、上限の外のパスを含むフィールドは設定の許可をそのまま残します。
- 対話UIがない場合、拒否または不正な要求は、プロセスを終了して理由をstderrに出します。それ以外の起動失敗では、ツールが使えない状態でセッションが残ります。

grantのパスは、読み込み時とマージ時に正規化します。許可済みのパスの上にsymlinkを被せると、次回のサンドボックス起動が失敗します。決まった権限が、`/hiraishi-network`、サブエージェント、host commandの上限になります。

## 開発

```sh
npm ci --ignore-scripts
npm run typecheck
npm test
```

- `HIRAISHI_REQUIRE_SANDBOX=1`：サンドボックスの前提が足りないとき、テストを失敗させます。
- `HIRAISHI_TEST_SOCAT=/absolute/path/to/socat`：テスト専用のsocatを指定します。

pi本体とインストール済みの拡張は、信頼するホストのコードとして扱います。
保護の範囲と制約の詳細は、[SECURITY.md](SECURITY.md)を参照してください。
